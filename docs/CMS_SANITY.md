# لوحة إدارة المحتوى (Sanity) — الإعداد والاستخدام

لوحة الإدارة مدمجة في الموقع على الرابط **`/admin`**، ومبنية على Sanity Studio.
- لا يوجد رابط لها في الموقع العام، ولا تظهر في محركات البحث (`noindex` و`robots.txt`).
- **الدخول يتم عبر حساب Sanity**، ولا يستطيع أحد التعديل إلا الأعضاء الذين تضيفهم إلى المشروع. من يعرف الرابط سيرى شاشة تسجيل الدخول فقط.
- لا توجد في كود المتصفح أي مفاتيح كتابة. القراءة العامة لا تشمل المسودات غير المنشورة.
- إلى أن تُضبط Sanity يعمل الموقع بالمحتوى المحفوظ في `content/*.json`، فلا شيء يتعطل.

---

## أولاً: الإعداد لمرة واحدة (حوالي 15 دقيقة)

### 1) إنشاء المشروع
1. ادخل إلى https://www.sanity.io/manage وسجّل بحساب Google أو GitHub أو البريد الإلكتروني. **هذا الحساب هو حساب المدير.**
2. اضغط **Create new project**، وسمِّه مثلاً `obaydah-portfolio`، واختر الخطة المجانية.
3. أنشئ Dataset باسم `production` بوضع **Public**. المحتوى المنشور عام أصلاً على الموقع، والمسودات تبقى محمية.
4. انسخ **Project ID** من صفحة المشروع.

### 2) متغيرات البيئة
محلياً في `.env.local`، وعلى الاستضافة (مثلاً Vercel → Settings → Environment Variables):
```
NEXT_PUBLIC_SANITY_PROJECT_ID=xxxxxxxx
NEXT_PUBLIC_SANITY_DATASET=production
SANITY_API_READ_TOKEN=...        # اختياري، للمعاينة قبل النشر
SANITY_REVALIDATE_SECRET=...     # نص عشوائي طويل، لتحديث الموقع فور النشر
```
- `SANITY_API_READ_TOKEN`: من **API → Tokens → Add API token** بصلاحية **Viewer**.
- `SANITY_REVALIDATE_SECRET`: ولّده بالأمر `openssl rand -hex 32`.
- لا تضع أي مفتاح سري في متغير يبدأ بـ `NEXT_PUBLIC_`.

### 3) السماح للوحة بالعمل من نطاقك (CORS)
في **API → CORS origins** أضف كلاً من الآتي مع تفعيل **Allow credentials**:
- `http://localhost:3000` (للتطوير)
- `https://نطاقك.com` (النطاق النهائي)
- نطاق المعاينة من Vercel إن كنت تستخدمه

### 4) الأعضاء والصلاحيات
- في **Members** ستجد حسابك بدور **Administrator**.
- لا تضف أي عضو آخر إلا إذا أردت. إن أضفت محرراً فاختر له دور **Editor** وليس Administrator.
- يُنصح بتفعيل التحقق بخطوتين في الحساب الذي تسجّل به (Google أو GitHub).

### 5) نقل المحتوى الحالي إلى اللوحة (مرة واحدة)
1. أنشئ مفتاحاً مؤقتاً بصلاحية **Editor** من **API → Tokens**.
2. نفّذ على جهازك:
   ```bash
   NEXT_PUBLIC_SANITY_PROJECT_ID=xxxxxxxx SANITY_API_WRITE_TOKEN=المفتاح npm run cms:seed
   ```
   ينسخ هذا الأمر الإعدادات، وقسم «عني» والأرقام والدول، والتخصصات، ومراحل العمل، والأسئلة الشائعة، ونصوص الاستشارة. لا يكتب فوق أي مستند موجود، وآمن إن أعدت تشغيله.
3. **احذف المفتاح المؤقت بعدها** من لوحة Sanity، ولا تضعه على الاستضافة.

### 6) تحديث الموقع فور النشر (Webhook)
في **API → Webhooks → Create webhook**:
- URL: `https://نطاقك.com/api/revalidate`
- Dataset: `production`، والتشغيل عند: Create وUpdate وDelete
- Filter: اتركه فارغاً، ولا تفعّل خيار المسودات (Drafts)
- Secret: القيمة نفسها التي وضعتها في `SANITY_REVALIDATE_SECRET`
- HTTP method: `POST`

بدون الـ webhook تظهر التعديلات أيضاً، لكن خلال 5 دقائق كحد أقصى بدل التحديث الفوري.

### 7) النشر
أعد نشر الموقع مرة واحدة بعد إضافة المتغيرات. بعدها **لا حاجة لإعادة النشر عند تعديل المحتوى**.

## ثانياً: الاستخدام اليومي

### الدخول
1. افتح `https://نطاقك.com/admin` (أو `http://localhost:3000/admin` محلياً، أو الملف `OPEN_ADMIN.cmd`).
2. سجّل الدخول بالطريقة التي أنشأت بها حساب Sanity (Google أو GitHub أو البريد).
3. تظهر لوحة «OBAYDAH HIJAZI» وفيها ثلاثة تبويبات في الأعلى: **المحتوى**، **الإحصائيات**، **معاينة**.

قائمة **المحتوى**:
- **الأعمال**
- **العملاء والشعارات**
- **آراء العملاء**
- **النصوص والتخصصات**: نبذة عني والأرقام والدول، والتخصصات، وعناوين الأقسام وطريقة العمل.
- **الأسئلة الشائعة**
- **الاستشارات وطلب عرض السعر**
- **إعدادات الموقع**: حالة استقبال المشاريع، والتواصل، وSEO، والموسيقى.

### رفع مشروع جديد
1. **الأعمال ← +**.
2. اكتب اسم المشروع، ثم اضغط **Generate** بجانب «المعرّف»، ثم اختر التصنيف.
3. ارفع **صورة الغلاف** واكتب وصفها بالعربية.
4. أضف صوراً أو فيديو MP4 مع غلافه في «صور وفيديوهات المشروع».
5. اختياري: اسم الجهة (بعد موافقتها)، والسنة، ووصف مختصر.
6. فعّل **مشروع مميز** ليظهر بعرض واسع في أعلى المعرض. يُنصح بأقوى ثلاثة أعمال.
7. اضغط **Publish**.
- **الترتيب:** بالسحب ⋮⋮. **الإخفاء:** «إخفاء من الموقع». **الحذف:** ⋯ ← Delete.
- **وسم تجريبي:** أي عنصر عليه هذا الوسم لا يظهر أبداً في الموقع المنشور.

### استبدال شعارات العملاء
1. **العملاء والشعارات ← +**. اكتب اسم الجهة، وارفع الشعار (SVG أو PNG شفاف)، وأضف الرابط إن أردت.
2. فعّل **«تمت الموافقة على نشر الشعار»**؛ الشعار لا يظهر بدونه.
3. **Publish**. الترتيب بالسحب، والإخفاء المؤقت بإلغاء «ظاهر في الموقع».
- الشعارات التجريبية (SAMPLE) تظهر فقط في التشغيل المحلي، وتختفي تلقائياً عند النشر.

### إضافة رأي عميل
**آراء العملاء ← +** ← النص والاسم والمنصب والجهة والشعار (اختيارية) ← فعّل «لدي موافقة صاحب الشهادة» و«منشور» ← **Publish**.
القسم يظهر في الموقع فقط عند وجود شهادة حقيقية واحدة على الأقل.

### تغيير حالة «متاح للمشاريع»
**إعدادات الموقع ← تبويب الافتتاحية ← حالة استقبال المشاريع**، ثم اختر:
- «متاح حالياً لاستقبال مشاريع جديدة»
- «جدول المشاريع مكتمل حالياً»
- «إخفاء الشارة»

ثم **Publish**. حتى تختار حالة، لا تظهر الشارة للزوار.

### الأرقام في «نبذة عني»
**النصوص والتخصصات ← نبذة عني والأرقام والدول ← الأرقام**. بطاقة «مشروع منجز» موجودة دون رقم، وتبقى **مخفية** في الموقع حتى تكتب العدد المؤكد وتنشر.

### تعديل الأسئلة الشائعة
**الأسئلة الشائعة**: عدّل السؤال أو الإجابة ثم **Publish**. الترتيب بالسحب، والإخفاء بإلغاء «منشور».

### متابعة الإحصائيات
تبويب **الإحصائيات**:
- **المحتوى:** أرقام حقيقية من اللوحة، مثل المشاريع المنشورة والمسودات والشعارات بانتظار الموافقة.
- **الزيارات والنقرات:** تظهر «لم يتم إعداد التحليلات» حتى تربط Umami (انظر `docs/ANALYTICS_AR.md`).
- **حجوزات Cal.com:** «غير متصل». الحجوزات المؤكدة تجدها في حسابك على Cal.com.

### المعاينة والنشر
- إذا ضُبط `SANITY_API_READ_TOKEN`: تبويب **معاينة** يعرض الموقع بالمسودات قبل نشرها.
- زر **Publish** ينشر التعديل. يظهر على الموقع فوراً إن أعددت الـ webhook، وإلا خلال 5 دقائق، دون إعادة نشر الموقع.


## إضافات الجولة الأخيرة
- **سياسة العمل والخصوصية**: مستند واحد فيه بنود الصفحتين `/terms` و`/privacy`.
- **المشاريع**: التصنيف يحدد المعرض (تصميم أو فيديو). حقل «اتجاه الصورة» اختياري، والعمودي يظهر ريلز.
- **الصور**: تحت كل حقل صورة المقاس المقترح، وتظهر ملاحظة تحذيرية (لا تمنع النشر) إذا كانت الصورة صغيرة.
