# تثبيت الموقع تقنياً — خطة التشغيل والأمان

## ما أُصلح بالكود
- صفحات الخدمات والمشاريع لها نفس الهيدر والفوتر وروابط صحيحة إلى الصفحة الرئيسية.
- معالجة أخطاء عربية وزر إعادة المحاولة؛ يُسجّل في سجلات Netlify معرّف خطأ ومسار مختصر فقط، وليس بيانات الزبون.
- فحوص PageSpeed وSanity تتطلب مفتاحاً خاصاً، مع حد مبدئي للطلبات. التقييد داخل ذاكرة وظيفة السيرفر هو حماية إضافية فقط، وليس بديلاً عن خدمة Rate Limiting موزعة عند التوسع.
- تحميل KO Sans مشروط بوجود الملفات المرخّصة وقت البناء. عند غيابها يستخدم الموقع IBM Plex Sans Arabic من دون 404.
- اختبارات متصفح لسطح المكتب والتابلت والموبايل؛ لا تُعتبر بديلاً عن اختبار Safari الأصلي على جهاز Apple.
- بعد أي تحديث للفرع main يتحقق GitHub Action من تطابق الإصدار المنشور على Netlify.

## إعدادات Netlify الضرورية
1. من **Environment variables** أضف `SITE_DIAGNOSTICS_SECRET`: عبارة عشوائية قوية من 24 حرفاً على الأقل، ويفضل 32+ حرفاً. لا ترسلها في دردشة ولا تضعها في GitHub.
2. أضف `NEXT_PUBLIC_SITE_URL` إلى رابط الموقع الرسمي HTTPS، مع مراعاة الدومين الذي ستعتمده.
3. اضبط `NEXT_PUBLIC_SANITY_PROJECT_ID` و `NEXT_PUBLIC_SANITY_DATASET` و `SANITY_API_READ_TOKEN` إن كنت تريد المعاينة قبل النشر.
4. في Sanity، اربط Webhook الموقع مع `/api/revalidate` وأضف `SANITY_REVALIDATE_SECRET` على Netlify (إن لم تكن إعداداته موجودة).
5. بعد كل تغيير بالمتغيرات نفّذ نشر جديداً.

### لوحة الجودة
- افتح `/admin` ← **الإحصائيات** ← أدخل قيمة `SITE_DIAGNOSTICS_SECRET` في حقل الفحص المحمي؛ تبقى القيمة في ذاكرة الصفحة فقط.
- اضغط فحص لقراءة PageSpeed واتصال Sanity ونسخة Netlify.
- عند غياب المفتاح سيرفض الخادم فحص الجودة؛ هذه حماية متعمدة ضد استهلاك الحصة من الزوار.

## تفعيل نشر Netlify تلقائياً والتحقق منه
- في Netlify تأكد أن **Continuous deployment** مرتبط بالمستودع `obaydahhijazi-blip/MY-WEBSITE` وفرع الإنتاج `main`.
- اضبط في إعدادات GitHub **Actions → Variables** المتغير `PUBLIC_SITE_URL` بعنوان موقعك المعتمد؛ إن غاب يستخدم الفحص الرابط المؤقت الحالي.
- يستقبل GitHub كل Push على `main` ويشغّل فحصاً متكرراً حتى يرى `COMMIT_REF` نفسه من `/api/site-version`. إذا لم يطابق خلال المهلة، تفشل مهمة `verify-production` ويظهر سبب التحقيق في Actions.
- **لا** يعني وجود هذا الفحص أن اتصال Netlify تم تلقائياً. لا بد من مراجعة واجهة Netlify إذا فشل.

## الخط KO Sans
- لا توجد ملفات خط مرخّصة داخل هذا المستودع العام. لا ترفعها إلا بعد التأكد أن الرخصة تسمح باستضافة Webfont لزوّار الموقع.
- تأكد من أسماء `KO-Sans-100.woff2` إلى `KO-Sans-700.woff2` أو OTF داخل `public/fonts/` ضمن بيئة البناء الآمنة.
- ينفذ `npm run prebuild` تلقائياً فحص الملفات وينشئ `styles/ko-sans-generated.css` بحسب الأوزان الموجودة فقط.
- إذا لم تتوفر الخطوط، فالخط الاحتياطي IBM Plex Sans Arabic هو العرض الرسمي الحالي، وليس خط KO Sans. هذا يمنع أخطاء تحميل الملفات ولا يستبدل ملف الترخيص.

## نسخ احتياطي مشفّر لـ Sanity
الجدول: كل يوم اثنين، مع إمكانية التشغيل اليدوي من **Actions → Encrypted Sanity backup → Run workflow**.

ضع **في GitHub Settings → Secrets and variables → Actions**:
- السر `SANITY_BACKUP_TOKEN`: رمز Robot *قراءة فقط* من Sanity للوصول إلى Dataset.
- السر `BACKUP_ENCRYPTION_PASSPHRASE`: عبارة سرية قوية 24+ حرفاً؛ احتفظ بنسخة خارج GitHub لأنها ضرورية للاستعادة.
- المتغير `SANITY_PROJECT_ID`: معرف مشروع Sanity الصحيح.
- المتغير `SANITY_DATASET`: مثل `production` (الافتراضي إذا لم تُضبط).

يسحب الـ Workflow تصديراً كاملاً يحتوي المستندات والوسائط، ويشفّره بأداة OpenSSL قبل رفع Artifact في Actions؛ مدة الاحتفاظ 30 يوماً. **لا يبدأ النسخ الحقيقي حتى تضبط المفاتيح وتنجح أول مهمة.**

### الاستعادة عند الحاجة (لا تتم تلقائياً)
1. نزّل ملف `sanity-backup.tar.gz.enc` من Artifact.
2. على جهاز آمن، فك التشفير باستخدام عبارة المرور المحفوظة، مثال:
```sh
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in sanity-backup.tar.gz.enc -out sanity-restored.tar.gz -pass env:BACKUP_ENCRYPTION_PASSPHRASE
```
3. استورد النسخة على **Dataset اختبار مستقل** أولاً عبر Sanity CLI، وتحقق من المشاريع والصور، ثم قرر الاستعادة على الإنتاج. لا تنفذ overwrite تلقائياً. حذف النسخة المستعادة غير المشفرة من القرص بعد اختبارها ضروري.

## التحقق النهائي
- `npm run check` يشغّل فحص TypeScript وESLint والبناء.
- GitHub Actions يفحص صفحات الخدمات و404 والروابط وخريطة الموقع.
- اختبارات Chromium على الهاتف/التابلت/الكمبيوتر تفحص أساسيات التنقل والطلب.
- تظل اختبارات Safari الفعلية، فتح Cal.com الحقيقي، رفع مشروع من Sanity وتأكيد ظهور المحتوى، والتأكد من وصول واتساب أموراً تحتاج اختباراً يدوياً من حساباتك.
