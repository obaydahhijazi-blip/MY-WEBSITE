# الحجز الحقيقي + إشعار واتساب — متطلبات التنفيذ

## المطلوب
- مدة الاستشارة: 30 دقيقة، مجانية.
- يستطيع الزائر اختيار وقت متاح فعلياً فقط بناءً على تقويم صاحب الموقع.
- بيانات الزائر: الاسم، الهاتف/واتساب، المجال، وصف مختصر اختياري، التاريخ والوقت والمنطقة الزمنية، مع معرف الحجز.
- تصل لصاحب الموقع رسالة واتساب بالمعلومات بعد **إنشاء حجز حقيقي**، وليس بعد مجرد الضغط على زر.

## الحل المقترح
1. تكوين حدث Cal.com مدته 30 دقيقة وربطه بتقويم حقيقي لتجنب التضارب.
2. تضمين الحجز داخل الموقع باستخدام Cal.com Embed.
3. تفعيل webhook لـ BOOKING_CREATED مع أحداث تعديل/إلغاء الحجز والتحقق من أصالة الطلب.
4. تمرير الحجز إلى تكامل WhatsApp Business Platform/Cloud API رسمي (أو مقدم معتمد)، مع موافقة/قوالب ورسوم عند اللزوم.
5. تخزين الحد الأدنى من المعلومات والأسرار على الخادم فقط، والتحقق من التكرار حتى لا يرسل الإشعار مرتين.

## حالة غير مفعّلة
حتى الآن لا يوجد رابط حدث Cal.com ولا بيانات API أو قوالب واتساب. لا تعتبر الرسائل التلقائية نشطة. `wa.me` يفتح رسالة مُجهزة لكن العميل يحتاج الضغط على إرسال؛ لا تُسمّ هذا إرسالاً تلقائياً.

## روابط معلومات رسمية
- https://cal.com/embed
- https://github.com/calcom/help/blob/main/webhooks.mdx
- https://whatsappbusiness.com/policy/

## مفاتيح البيئة المتوقعة
`NEXT_PUBLIC_CAL_EVENT_LINK`, `CAL_WEBHOOK_SECRET`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_TEMPLATE_NAME`, `WHATSAPP_OWNER_NUMBER`. لا تضع أي أسرار في `NEXT_PUBLIC_*`.

## نموذج التنبيه المفضل
طلب استشارة مجانية جديد — الاسم، هاتف التواصل، نوع المشروع، ملخص المشروع، التاريخ الكامل، التوقيت المحلي + المنطقة الزمنية، معرف الحجز، رابط المكالمة إذا كان متاحاً.
